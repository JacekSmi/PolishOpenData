# Test fixtures

Recorded upstream responses that the unit tests replay offline. Each file holds a single response.

- **Sources:** `krs/` comes from the KRS Open API (`api-krs.ms.gov.pl`) of the Ministry of Justice, `bialalista/` from the VAT whitelist API (`wl-api.mf.gov.pl`) of the Ministry of Finance. Retrieved on 2026-09-24; `full-P-0000106150-removed-trimmed.json` is shortened.
- **Basis:** the KRS Open API is listed on dane.gov.pl (dataset 27606, "API Krajowego Rejestru Sądowego (API KRS)") under CC0 1.0. The Biała Lista responses are public register data published by the Ministry of Finance; no licence is claimed for them.
- **Masking:** natural persons in KRS appear only as masked by the Ministry of Justice (for example `F*****`). Free text that can hold names or PESEL numbers is replaced with `[REDACTED]`: `rodzajProkury`, the `umowaStatut` entries and the notary names inside dzial6 merger/split descriptions. Biała Lista representatives are replaced with `JAN KOWALSKI`.
- **Synthetic files:** `synthetic-*` files are hand-made, not recorded, and cover cases that cannot be triggered safely or on demand against the live API (daily-limit and database-update errors, null arrays with an unknown field).

- **GUS REGON (`regon/`):** the `*.mtom` + `*.headers` pairs are byte-for-byte copies of responses of GUS's public BIR1.2 **test environment** (`wyszukiwarkaregontest.stat.gov.pl`: a complete but not updated, anonymised copy of the register, most records as of 2014-11-08), recorded on 2026-10-03 (`zaloguj-ok` = capture `01_zaloguj_A`, the login answer; `search-regon-gus` = `03_search_with_A_after_B_login`, GUS's search row; `wyloguj-true` = `04_wyloguj_A`, the logout answer; `search-empty` = `05_search_with_logged_out_A` and `getvalue-empty` = `06_getvalue_komunikatkod_dead_A`, the empty answers of a dead session) and on 2026-09-28 (`fault-sender-500` = `body_r6_wrongto`, the HTTP 500 SOAP Sender fault for a wrong `wsa:To`), and on 2026-10-04 (`report-osprawna-gus` = capture `capture-03`, the `BIR12OsPrawna` full report of GUS itself, 41 filled fields; `getvalue-standanych` = `capture-04`, the `GetValue("StanDanych")` answer, data date 19-10-2018). The phone, fax, e-mail and web address in `report-osprawna-gus` are GUS's own institutional contact data. The service writes the later parameters of the `Content-Type` without a space after the semicolon (`...;start="...";boundary="..."`), as these two `.headers` files and `fault-sender-500.headers` show; the other `.headers` files hold the spaced form. `.headers` holds the HTTP status and the verbatim `Content-Type`. Recorded fixtures are legal entities only (GUS itself, REGON `000331501`); the session id in `zaloguj-ok` is a synthetic one of the real length, and no key or production data appears anywhere. `.gitattributes` marks the folder `-text` so that the CRLF framing is kept: copy with `cp`, do not edit. The raw captures and the research notes live outside the repository.
- **GUS REGON synthetic files:** `regon/synthetic-*.xml` and `regon/synthetic-getvalue-standanych.txt` hold the inner result of one BIR operation (the test helpers wrap them in the MTOM framing). They are hand-made with invented values, because the real responses were not recorded (full reports other than GUS's own `BIR12OsPrawna`, error codes) or concern natural persons (`JAN KOWALSKI` and the identifiers of GUS's test database). `synthetic-report-osprawna-gus.xml` carries all 55 fields of `BIR12OsPrawna`. `123456785` (REGON) and `1234563218` (NIP) are checksum-valid placeholders for an invented legal person, not identifiers of the test database; the 14-digit local-unit numbers extend a REGON of the test database or GUS's own (`14239685800010`, `99999999000026`, `00033150100017`). `synthetic-search-control-char.xml` holds one raw U+001F control character in its name on purpose (the helper writes it as `&#x1F;` in the envelope, as WCF does); keep it when editing the file.
- **GUS REGON field list:** `regon/bir12-field-names.tsv` (`report<TAB>field`, 427 lines for the 17 BIR1.2 full reports) was first reconstructed from BIR1.1 element lists plus the documented BIR1.2 changes, and on 2026-10-04 it was checked against the element names of the official BIR1.2 report XSDs (GUS documentation version 1.4; the XSDs are in GUS's documentation archive, not in this repository). 15 of the 17 reports matched; the two natural-person PKD reports (`BIR12OsFizycznaPkd`, `BIR12JednLokalnaOsFizycznejPkd`) differed in four names each (`fiz_pkdKod` and the rest, not `fiz_pkd_Kod`) and were corrected, so the list now equals the XSD element names. The XSDs are the authority: fields that the test environment leaves empty were not seen on the wire. The drift-guard test compares the list with the mapper; check it against the XSDs again when GUS changes the service (the law changes on 2026-12-17/18).
- **GUS REGON names seen live:** `regon/observed-field-names-test-env.tsv` (`report<TAB>name`, LF, 97 lines in 5 reports) lists the field names that the test environment sent on 2026-10-04 for the entities `000331501` (GUS), `999999990` and `021625560` of the test database. It holds names only, no values: the answers about natural persons were not recorded. A test checks that every pair is in the field list. The entity `021625560`, removed before 2014, answered both `BIR12OsFizycznaDaneOgolne` and `BIR12OsFizycznaDzialalnoscSkreslonaDo20141108`, so the reports the client picks for that silo (silo 4) work against the real service.
