# Test fixtures

Recorded upstream responses that the unit tests replay offline. Each file holds a single response.

- **Sources:** `krs/` comes from the KRS Open API (`api-krs.ms.gov.pl`) of the Ministry of Justice, `bialalista/` from the VAT whitelist API (`wl-api.mf.gov.pl`) of the Ministry of Finance. Retrieved on 2026-09-24; `full-P-0000106150-removed-trimmed.json` is shortened.
- **Basis:** the KRS Open API is listed on dane.gov.pl (dataset 27606, "API Krajowego Rejestru Sądowego (API KRS)") under CC0 1.0. The Biała Lista responses are public register data published by the Ministry of Finance; no licence is claimed for them.
- **Masking:** natural persons in KRS appear only as masked by the Ministry of Justice (for example `F*****`). Free text that can hold names or PESEL numbers is replaced with `[REDACTED]`: `rodzajProkury`, the `umowaStatut` entries and the notary names inside dzial6 merger/split descriptions. Biała Lista representatives are replaced with `JAN KOWALSKI`.
- **Synthetic files:** `synthetic-*` files are hand-made, not recorded, and cover cases that cannot be triggered safely or on demand against the live API (daily-limit and database-update errors, null arrays with an unknown field).

- **GUS REGON (`regon/`):** the `*.mtom` + `*.headers` pairs are byte-for-byte copies of responses of GUS's public BIR1.2 **test environment** (`wyszukiwarkaregontest.stat.gov.pl`: a complete but not updated, anonymised copy of the register, most records as of 2014-11-08), recorded on 2026-10-03 (`zaloguj-ok` = capture `01_zaloguj_A`, the login answer; `search-regon-gus` = `03_search_with_A_after_B_login`, GUS's search row; `wyloguj-true` = `04_wyloguj_A`, the logout answer; `search-empty` = `05_search_with_logged_out_A` and `getvalue-empty` = `06_getvalue_komunikatkod_dead_A`, the empty answers of a dead session) and on 2026-09-28 (`fault-sender-500` = `body_r6_wrongto`, the HTTP 500 SOAP Sender fault for a wrong `wsa:To`). `.headers` holds the HTTP status and the verbatim `Content-Type`. Recorded fixtures are legal entities only (GUS itself, REGON `000331501`); the session id in `zaloguj-ok` is a synthetic one of the real length, and no key or production data appears anywhere. `.gitattributes` marks the folder `-text` so that the CRLF framing is kept: copy with `cp`, do not edit. The raw captures and the research notes live outside the repository.
- **GUS REGON synthetic files:** `regon/synthetic-*.xml` and `regon/synthetic-getvalue-standanych.txt` hold the inner result of one BIR operation (the test helpers wrap them in the MTOM framing). They are hand-made with invented values, because the real responses were not recorded (full reports, the data date, error codes) or concern natural persons (`JAN KOWALSKI` and the identifiers of GUS's test database). `synthetic-report-osprawna-gus.xml` carries all 55 fields of `BIR12OsPrawna`.
- **GUS REGON field list:** `regon/bir12-field-names.tsv` (`report<TAB>field`, 427 lines for the 17 BIR1.2 full reports) is **reconstructed**, not copied from the BIR1.2 XSDs (which are in GUS's documentation archive, not in this repository): it comes from the BIR1.1 XSD element lists of a third-party mirror plus the documented BIR1.2 changes. The drift-guard test compares it with the mapper only; the list must be diffed against the XSDs before the 1.2.0 tag, and again when GUS changes the service (the law changes on 2026-12-17/18).

New fixtures must follow the redaction rules in [CONTRIBUTING.md](../../CONTRIBUTING.md).
